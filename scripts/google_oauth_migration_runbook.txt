SECTION 2 - OAuth scopes the code requests (for the consent screen "Data access" page)
=======================================================================================

Each flow is a SEPARATE consent that asks only for its own scopes.

  Flow             Scope                                                    Class
  ---------------  -------------------------------------------------------  -------------
  Google sign-in   openid                                                   non-sensitive
  Google sign-in   https://www.googleapis.com/auth/userinfo.email (email)   non-sensitive
  Google Ads       https://www.googleapis.com/auth/adwords                  sensitive
  Merchant Center  https://www.googleapis.com/auth/content                  sensitive
  YouTube          https://www.googleapis.com/auth/youtube.upload           sensitive
  YouTube          https://www.googleapis.com/auth/youtube.readonly         sensitive
  Tag Manager      https://www.googleapis.com/auth/tagmanager.edit.containers         sensitive
  Tag Manager      https://www.googleapis.com/auth/tagmanager.edit.containerversions  sensitive
  Tag Manager      https://www.googleapis.com/auth/tagmanager.publish                 sensitive

- No RESTRICTED scope is requested by any consent flow.
- The Drive scope (https://www.googleapis.com/auth/drive) is used ONLY by the service
  account. It is NOT a user consent - do NOT add it to the consent screen.
- When you add each scope, the console shows its class. If the console's class differs
  from this table, the console is right - note it and tell Claude.
- The written justification for every scope is in docs/GOOGLE-SCOPES.md (repo).

Env vars the code reads for Google (agents/keys_agent.py and core/*_service.py):
  GOOGLE_OAUTH_CLIENT_ID ........ OAuth client ID (all 5 flows)              -> CHANGES
  GOOGLE_OAUTH_CLIENT_SECRET .... OAuth client secret (all 5 flows)          -> CHANGES

  GOOGLE_ADS_LOGIN_CUSTOMER_ID .. optional Ads manager account id            -> stays
  YOUTUBE_DATA_API_KEY .......... plain API key, YouTube niche search        -> step 4f

  PUBLIC_APP_URL ................ base of every redirect URI                 -> stays
Whether each is a plain Cloud Run env var or a Secret Manager reference is NOT in the
code - step 4a prints it from the live service.

SECTION 5 - What clients must do, and what is broken until they do
=======================================================================================

Why: a Google grant belongs to the OAuth client that created it. After the switch, every
stored Google refresh token (made with the old client) is rejected. Nothing is lost on
our side - the client just has to approve again.

STEP 5a - SQL - Who must reconnect what (run BEFORE the switch; save the result)
----- copy from here -----
select client_id, string_agg(platform, ', ' order by platform) as must_reconnect
from client_accounts
where platform in ('google_ads', 'youtube', 'youtube_pending', 'google_tagmanager',
                   'merchant_center', 'merchant_center_pending')
group by client_id
order by client_id;
----- copy until here -----

What each client does: open the dashboard, and on each Google card listed for them press
Connect / Reconnect. If the card only offers Disconnect, press Disconnect, then Connect.
  - Google Ads: may ask again which ad account to manage.
  - Merchant Center: they type their Merchant Center id again.
  - YouTube, Tag Manager: approve and done.
  - Google sign-in: nothing to do. It keeps working (Google identifies the person the
    same way across projects); they see the new consent screen once.
Optional for clients: remove the old "uallak" entry at
https://myaccount.google.com/permissions (Disconnect in our dashboard also removes it).

What STOPS working for a client until they reconnect:
  - Google Ads: dashboard numbers, weekly report, sales-alert emails, keyword/ad-copy
    optimization, campaign creation, AND the health scan that auto-pauses campaigns with
    disapproved ads (a safety net - reconnect clients with live ad spend FIRST).
  - YouTube: publishing videos, view/like/comment counts.
  - Tag Manager: setting up or checking the lead conversion tag. Tags that are ALREADY
    published in their container keep working - they live in Google, not with us.
  - Merchant Center: feed status.
  - Expect a burst of admin alerts about failed Google tokens - that is this, not a bug.
What keeps working: Google sign-in, Drive media folders (service account), YouTube niche
search (API key), Meta, TikTok, WordPress and everything else.
